# Atlas Offensive — Complete Research Sequence

Narrative companion to `atlas_offensive_future_run_registry.csv` (47 runs) and
`atlas_offensive_run_dependency_graph.md`. Duration classes assume a solo
researcher with Fable-5-assisted sprints; calendar estimates are planning
aids, not commitments.

## Stage 0 — Foundation (immediately; days–weeks)

**R00 Governance reset** → **R01 PIT breadth confirmation.**
Everything downstream inherits R00's registry/holdout/cost rules. R01 is the
cheapest high-conviction test in the program and doubles as the Norgate
onboarding exercise.

## Stage 1 — Internal unlocks on the existing stack (weeks 2–10)

**R02 Regime offensive rebuild (native PBI + jump-model benchmark).**
Runs on existing data. Attacks the single largest documented opportunity
(early-recovery capture). Its output — an offense-capable state machine —
becomes the conditioning layer for every later engine.

Parallel starters: **R08 futures track** and **R13 options data foundation**
can begin here if capital/data decisions (G08, ORATS) are made early.

## Stage 2 — The breadth platform (months 1–4)

**R03 stock universe + momentum** → **R04 concentrated long-only** and
**R06 factor library**; then **R05 long/short v1**.
R03/R04 produce the first deployable offensive product (a concentrated
long-only compounder) while R05/R06 establish whether true alpha (not fuller
beta) is available at retail economics. **Decision point D1** after R04/R05:
if long/short economics fail, the platform identity collapses gracefully to
Aggressive Long-Only + Futures + Options — that is a finding, not a failure.

## Stage 3 — Parallel engine tracks (months 3–9, overlapping)

- **Equity extensions:** R07 stat arb (needs R05 pass), R12 earnings/PEAD,
  R11 event-driven, R19 free alt-data, R20 LLM text signals.
- **Futures/macro:** R08 trend → R09 macro conditioning v2 → R10 cross-asset
  carry → R21 crypto sleeve.
- **Options:** R13 vol forecasting → R14 defined-risk VRP and R15 recovery
  convexity (R15 also needs R02's states) → R16 dispersion feasibility note.
- **Short-horizon:** R17 overnight/daily effects → R18 swing systems
  (both gated on intraday infrastructure, gap G06).

**Decision point D2** (~month 6): rank engines by evidence; kill tracks that
hit their pre-registered failure conditions; carry 3–5 forward.

## Stage 4 — The ML ladder (months 4–10, on the Stage 2 panel)

**R22 GBM ranking engine** (the workhorse) → **R23 targets laboratory** →
benchmarks **R24 CNN → R25 RNN/SSM → R26 transformers → R27 GNN → R29 TSFM**
(each must beat its predecessor to continue; expected outcome per current
evidence: the ladder stops early and GBM stands) → **R28 SSL embeddings →
R30 analog retrieval v2** → **R31 decision-focused learning** →
**R34 automated discovery with guardrails**.

## Stage 5 — Moonshot mathematics (opportunistic, months 6–12)

R35 MPC rebalancing, R36 spectral features, R37 transfer-entropy lead-lag,
R38 geometry/signatures/OT/DRO, R39 network crowding, R40 causal robustness
screens, R41 complex-systems indicators. Each is a bounded experiment with
negative-control framing; each can run in a gap week between core sprints.

## Stage 6 — Integration (months 9–15)

**R42 sizing laboratory** (needs ≥3 alpha runs complete) → **R43 dynamic
leverage ≤1.5×** (needs owner capital declaration) → **R44 multi-strategy
capital allocation** (needs ≥3 engines in paper) → **R33 generative stress
engine** and **R35** feed R44's robustness.

## Stage 7 — Risk engineering and deployment (months 12–18)

**R45 drawdown engineering** — now, and only now, tail risk is removed at a
priced return give-up (budget ≤20% of CAGR) → **R47 paper-trading gate**
(13+ weeks live-shadow within backtest confidence bands; human authorization
required for any real capital) → **R46 execution/cost engine** runs
continuously from first paper trade → **R32 execution RL** only if R46's
rule-based baseline leaves measurable shortfall on the table.

## Standing rules across all stages

1. Every run pre-registers candidates, gates, and stop rules before execution.
2. Every result table decomposes return (beta/factors/leverage/carry/timing/
   selection/sizing) and reports the trial count behind it.
3. Branches die by their own declared stop rules (Frontier-2 precedent) and
   stay dead unless *new data* (not new enthusiasm) reopens them.
4. The defensive Atlas core remains untouched production throughout; Atlas
   Offensive earns capital allocation only through the R47 gate.
5. The registry and this sequence are living documents: runs may split,
   merge, or reorder as evidence arrives — with edits logged.
